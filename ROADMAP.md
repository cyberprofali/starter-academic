# Site improvement roadmap

## Guiding outcome

Keep [alihmd.com](https://alihmd.com) accurate, professional, accessible, fast, and easy to maintain. Prefer small, reviewable improvements over broad rewrites.

## Current priorities

- [x] Add repository-level Codex guidance.
- [x] Replace the upstream starter README with project documentation.
- [x] Add a pull-request template.
- [ ] Add a reproducible build check that uses the site's pinned Hugo version.
- [ ] Audit and remove starter content, editor artifacts, and unused files without deleting personal material.
- [ ] Check biography, navigation, contact methods, projects, publications, and resume links for accuracy.
- [ ] Establish a visual baseline with desktop and mobile screenshots.
- [ ] Improve accessibility, mobile layout, metadata, and performance based on the baseline.
- [ ] Plan the legacy Hugo and Wowchemy upgrade as a separate migration with preview and rollback steps.

## How Codex should use this roadmap

When a request is broadly phrased as “improve the site” or “make it nicer,” choose the first unchecked item that can be completed safely in one focused pull request.

For every improvement:

1. Inspect the relevant existing files before editing.
2. Preserve personal facts unless the requested change supplies updated information.
3. Validate the build or clearly state why it could not be run.
4. Include screenshots when appearance changes.
5. Open or update a pull request for review.
6. Never merge or deploy automatically.

The roadmap is direction, not permission to publish unreviewed content, change credentials, alter personal claims, or perform a framework migration without explicit approval.
